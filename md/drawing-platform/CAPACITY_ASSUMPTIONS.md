# Chosen BOTEC capacity budgets

**Design assumptions, not benchmarks.** All numbers are rounded. Target **at least 50% spare safe capacity at normal peak**; flash is twice peak. `Demand / safe capacity` makes utilization visible. A node operation is work at one replica, not necessarily one client request. Fixed small operations/objects, balanced placement, and the stated miss mix are assumed; the reserved half covers skew, retries and background work.

| Design | Average / peak / flash client QPS | Chosen safe physical capacity | Peak utilization → flash |
| --- | --- | --- | --- |
| Financial cache | 1k / 4k / 8k; 50% reads; 10% read misses | 1 LB ×50k QPS; 1 app ×10k QPS; 3 cache ×50k node ops/s; 3 Cassandra ×5k node ops/s | LB 8→16%; app 40→80%; cache 7→14%; **DB 43→85%** |
| Feed cache | 2k / 10k / 20k; 99% reads; 9% read misses | 2 API ×10k QPS; 3 cache ×50k ops/s; 3 DB ×1k ops/s | **API 50→100%**; cache 9→17%; DB 40→79% |
| KV | 1k / 4k / 8k; half GET/PUT | LB 50k; gateway 20k; coordinator 10k QPS; B/C/E each 10k ops/s; D down | LB 8→16%; gateway 20→40%; coordinator 40→80%; E 43→77% |
| CDN | 3k / 15k / 30k; 20 KB objects | 3 edges ×10k QPS (200 MB/s each); parent 10k; origin 1k QPS; routing 50k lookups/s | **Edges 50→100%**; parent 15→30%; origin 30→60%; routing 3→6% |

- **Financial:** charge all traffic to the three shown B nodes. Peak cache work = `2×2k reads + 3×2k writes + 3×200 refills = 10.6k ops/s`, or ~3.5k/50k per host. `3×50k=150k` raw node ops/s permits at most **75k read-only quorum client QPS**, before writes/refills. Cassandra work = `3×2k writes + 2×200 fallback reads = 6.4k/15k ops/s`, ~2.13k/5k on each explicitly assumed host. RF=3 does not itself imply three machines; three machines is a separate sizing choice. Cassandra is the first linear saturation limit (~9.4k client QPS); flash already misses the 50% spare target. One lost cache host leaves 100k raw ops/s. One lost DB host leaves 10k raw ops/s: conservative peak 64%, flash 128%, explicitly unsafe for the target.
- **Legacy vault cache drawing:** its nine physical cache machines retain 50k ops/s each (450k raw total); spread the same 10.6k peak work uniformly over its three shards, ~1.2k/50k per machine. Logical shards never gain an independent budget. Application host is an assumed host identified in the annotation, absent from the original artwork.
- **Feed:** peak 9900 reads +100 writes; 891 misses, one bounded DB query/miss. Three DB hosts = primary plus two read replicas, balanced reads: `891 + 3×100 = 1191/3000 node ops/s` (~397/1000 each). Cache `9900 + 3×891 refills + 3×100 invalidations = 12873/150000`, ~4291/50000 each. API safe budgets include this rebuild mix. Cold cache drives DB to `9900+300=10200/3000` (**340% overload**). API flash reaches 100%; this design deliberately marks the limit instead of implying spare capacity.
- **KV:** two replica reads and three-copy writes give `2×2k + 3×2k = 10k` foreground ops/s across B/C/E. Fixed extra 1k handoff ops/s at E gives 11k/30k total and ~4.3k/10k at E. D has zero available capacity while down; after recovery it spends 1k/10k on receiving handoff. At flash the coordinator is 80% and E ~77%, both miss the target. With fixed handoff demand the coordinator saturates first at 10k client QPS, even though E is busiest at normal peak.
- **CDN:** balanced peak 5k/10k QPS per edge, 100/200 MB/s each. 90% edge hits →1.5k/10k parent QPS; 80% parent hits →300/1k origin QPS. Edge RAM/SSD assumption: 20/64 GB resident per host; cached-object icons share these same hosts. One edge fails →7.5k/10k per survivor (75%, headroom failure). No parent →1.5k/1k origin (**150% overload**); fully cold caches →15k/1k. Control and placement each have one host: 100/1k updates/s and 300/1k background copies/s, respectively.
- **Telemetry:** two events/client request; one collector per design. Financial 8k/50k, feed 20k/50k, CDN 30k/100k events/s at peak. CPU/network/ingestion work consumes these budgets. KV has no separate collector drawn.

Baseline method: the vault's **BOTEC — Start Here**, **⚙️ BOTEC — CPU Work → Time → Throughput**, and **⚙️ Functional BOTEC — Deriving Step Costs (No Magic Numbers)**. The 50k cache, 10k API, 5k Cassandra and other safe budgets are **explicit choices for this exercise**, using the earlier reference ranges as context, not claimed derivations or production measurements. Capacity refers to physical hosts; libraries, shard IDs and repeated host views are not extra machines. The application source-code diagram remains outside runtime sizing scope.
